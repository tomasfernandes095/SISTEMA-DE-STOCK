Conseguir criar uma base de dados SQLite.

Ainda não vamos fazer login, Excel, POO, segurança, etc.

🟢 FASE 3 — CRUD

CRUD é uma palavra extremamente importante em programação.

Significa:

C → Create
R → Read
U → Update
D → Delete

Ou seja:

CRIAR produto
      ↓
CONSULTAR produto
      ↓
ALTERAR produto
      ↓
ELIMINAR produto

Vais criar funções para:

adicionar_produto()
listar_produtos()
procurar_produto()
alterar_produto()
eliminar_produto()
🟡 FASE 4 — Sistema de stock

Agora entram as operações:

Entrada

Entrada: +20

Novo stock: 70
Saída
Arroz
Stock atual: 70

Saída: -15

Novo stock: 55

Stock: 5

🟡 FASE 5 — Código automático

O sistema deverá gerar:

001
002
003
004
...

Mas existe uma regra importante:

Se:

001
002
003

e eliminares:

002

o próximo não será 002.

Será:

004

Isto obriga-te a pensar sobre a diferença entre:

ID da base de dados

e

Código do produto

É uma ótima oportunidade para aprenderes algo importante de bases de dados.

🔐 FASE 11 — Segurança das passwords

Aqui nunca fazemos:

password = "123456"

guardada diretamente na base de dados.

Utilizamos hashing através de uma biblioteca adequada.

O objetivo é que a base de dados tenha algo semelhante a:

username: tomas
password_hash: $2b$12$........

e não:

username: tomas
password: 123456

🛡️ FASE 15 — Validação

Agora vamos tornar o programa resistente a erros do utilizador.

Por exemplo:

Nome:
[ENTER]

❌ O nome não pode estar vazio.

Ou:

Quantidade:
-50

❌ A quantidade não pode ser negativa.

Ou:

Preço:
abc

❌ Introduza um número válido.
🛡️ FASE 16 — SQL Injection

Aqui vais aprender uma coisa muito importante de segurança.

Nunca devemos construir queries perigosamente com strings introduzidas pelo utilizador.

Vamos aprender a utilizar:

queries parametrizadas

Isto é essencial quando trabalhas com bases de dados.

💾 FASE 17 — Backups

Vamos criar:

backups/

E o programa poderá fazer cópias da base de dados.

Por exemplo:

backups/
│
├── stock_2026-08-28.db
├── stock_2026-08-29.db
└── stock_2026-08-30.db

Assim, se a base de dados principal ficar corrompida, tens uma cópia.
